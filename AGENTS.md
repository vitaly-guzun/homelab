# Project instructions

## Review, commit, and push

- Do not create Git commits or push changes unless the user explicitly changes
  this instruction.
- Implement requested changes and perform appropriate checks, then show the
  user the result, the validation performed, and any remaining limitations.
- Leave changes uncommitted for the user's review. After accepting the result,
  the user commits and pushes the changes themselves. Acceptance alone does
  not authorize the agent to commit or push.
- Do not treat an implementation or deployment request as permission to commit
  or push. If Flux deployment requires a push, explain that the user's commit
  and push are required before deployment can be verified.
